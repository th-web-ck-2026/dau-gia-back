01. Chung

Bản đồ nghiệp vụ

Hệ thống cần phân biệt rõ đấu thầu và đấu giá. Đấu thầu chọn nhà thầu tốt nhất dựa trên scoring đa tiêu chí. Đấu giá chọn người thắng dựa trên giá, cam kết và uy tín, có cập nhật realtime.

Tendering

Đấu thầu

Score-based
  • Mục tiêu: chọn nhà thầu có tổng điểm cao nhất.
  • Đầu vào: proposal, giá đề xuất, hồ sơ năng lực, criteria values.
  • Chấm điểm: sàng lọc pass/fail, technical score, price score, final score.
  • Kết quả: ranking, winner, breakdown điểm và audit log.

Auction

Đấu giá

Realtime
  • Mục tiêu: xác định người trả giá hợp lệ và có ưu tiên cao nhất.
  • Đầu vào: giá khởi điểm, bước giá, bid amount, đặt cọc, lịch sử uy tín.
  • Chấm điểm: price score, commitment score, trust score.
  • Kết quả: current winner, next valid bid, bid history và biên bản.

Host/Owner

Tạo phiên, cấu hình criteria, publish, theo dõi ranking, close và công bố kết quả.

Bidder/Participant

Đăng nhập, nộp proposal hoặc đặt giá, theo dõi trạng thái và hoàn tất thủ tục nếu thắng.

Admin

Kiểm duyệt phiên, quản lý người dùng, khóa tài khoản vi phạm và xử lý tranh chấp.

System

Validate, score, rank, realtime update, auto open/close và ghi audit log.

02. Scoring

Công thức và quy tắc tính điểm

Technical Score

Dùng cho đấu thầu. Nếu điểm kỹ thuật nhỏ hơn ngưỡng tối thiểu thì loại trước khi so sánh final score. 

T = exp x 0.4 + finance x 0.3 + trust x 0.3
if T < 50 => REJECTED

Tender Price Score

Đấu thầu ưu tiên giá thấp hợp lệ. Giá phải lớn hơn 0 và không vượt giá trần nếu phiên có cấu hình ceiling price. 

P = (Gmin / Gi) x 100
Total = T x 0.6 + P x 0.4

Auction Price Score

Đấu giá ưu tiên giá cao hợp lệ. Mỗi bid mới phải đạt tối thiểu current price cộng bid increment. 

Pi = (Gi / Gmax) x 100
newBid >= current + increment

Criteria normalization

Loại criteria Hướng tốt hơn Công thức/rule Edge case
number / percent Cao hơn hoặc thấp hơn tùy isReverse Min-max về thang 0-100 max == min thì score = 100
boolean true/false theo cấu hình true = 100, false = 0 Có thể dùng làm hard constraint
enum Theo mapping basic = 40, standard = 70, premium = 100 Reject nếu value không nằm trong options
document Hợp lệ/không hợp lệ Pass/fail hoặc admin review Thiếu tài liệu required thì REJECTED

04. BACK

Kiến trúc backend NestJS

Backend tách scoring, tender, auction và audit để controller mỏng, service rõ trách nhiệm, dễ test và dễ mở rộng realtime.

scoring

Formula, normalize, weighted score, price score, final score.

tender

Tender session, criteria, submission, value, ranking.

auction

Auction session, bid, transaction, current price, winner.

audit-log

Log action quan trọng: publish, submit, bid, close, cancel.

Database lõi cho đấu thầu

  • tender_sessions: title, hostId, status, time, weights, winner.
  • tender_criteria: code, type, weight, isReverse, hard constraint.
  • tender_submissions: bidderId, price, technicalScore, priceScore, totalScore.
  • tender_submission_values: raw value, normalized score, weighted score.

Database lõi cho đấu giá

  • auction_sessions: startPrice, currentPrice, increment, currentWinnerId.
  • auction_bids: userId, bidAmount, score, serverSequence, placedAt.
  • audit_logs: actorId, action, targetType, before, after, metadata.
  • cron-job: auto open/close sessions by startTime and endTime.

Transaction bắt buộc cho đấu giá

1. Lock session
2. Read price
3. Validate bid
4. Create bid
5. Commit winner

06. Verify

Checklist chuẩn trước khi build

Business

  • Scoring đấu thầu và đấu giá tách rõ.
  • Có hard constraints trước scoring.
  • Có trạng thái session và submission/bid.
  • Có audit cho action quan trọng.

WEB

  • Có loading, empty, error state.
  • Form động theo criteria type.
  • Countdown dùng server time.
  • Ranking realtime hoặc polling fallback.

BACK

  • Scoring service có unit test.
  • Bid đấu giá dùng transaction.
  • Swagger có request/response mẫu.
  • E2E có happy path tender và auction.
